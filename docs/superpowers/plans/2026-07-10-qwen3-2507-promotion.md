# Qwen3-4B-Instruct-2507 Promotion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Phase-1 Gate G1 and Phase-2 Gate G2 are CONTROLLER-ONLY — never dispatch a subagent for them (hardware/LLM-gated).**

**Goal:** Make `Qwen3-4B-Instruct-2507` the default on-device note-generation LLM, replacing Llama-3.2-3B, gated on an eval that proves it beats the 3B synthesis ceiling without JA-purity regressions.

**Architecture:** Two phases with a hard gate. Phase 1 wires a 2507 eval profile and the controller runs a reboot-gated eval (interactive, 8GB machine) — a STOP verdict ships nothing. Phase 2 (SDD) swaps the production catalog default, promotes the profile, conditionally adds a deterministic zh→JA glyph-normalize pass, and bumps the app version.

**Tech Stack:** TypeScript, Electron, llama.cpp sidecar (embedded GGUF chat template — no C++ rebuild), Vitest, pnpm workspaces.

**Spec:** `docs/superpowers/specs/2026-07-10-qwen3-2507-promotion-design.md`

## Global Constraints

- **8GB M3 hardware rule:** one LLM model foreground at a time; `pkill -9 -f llama-completion` between runs; reboot if `sysctl vm.swapusage` > 1.5 GB. **NEVER** run LLM inference (eval, `pnpm verify/test/dev/smoke`) with `run_in_background:true` — vitest/electron re-forks stack processes → kernel panic.
- **No C++ rebuild:** 2507 is the same Qwen3 architecture the current sidecar supports; `chatTemplate: 'auto'` reads the GGUF-embedded template. Do not touch `desktop/sidecar/`.
- **License:** 2507 is Apache-2.0 (commercial OK) — preserved reason Qwen3 beat Qwen2.5-3B.
- **GGUF source:** `unsloth/Qwen3-4B-Instruct-2507-GGUF`, file `Qwen3-4B-Instruct-2507-Q4_K_M.gguf` (no official Qwen GGUF exists). Download URL: `https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF/resolve/main/Qwen3-4B-Instruct-2507-Q4_K_M.gguf`.
- **Measured values only:** `sizeBytes` and `sha256` in `catalog.ts` come from `stat -f%z` / `shasum -a 256` of the exact downloaded file — never guessed.
- **Version bump:** bump `desktop/package.json` `version` by `+0.0.1` **from the branch's live value at promotion time** (currently 0.1.39 in this worktree; do not hardcode — read it).
- **Naming trap:** the existing `qwen3-4b-q4-km` profile's `filename` is `Qwen3-4B-Instruct-Q4_K_M.gguf` — that file is the **base hybrid** model, NOT 2507. The 2507 file has a distinct `…-2507-…` name. Keep them separate.
- **pre-push:** `pnpm lint` (not just `tsc`) — `desktop-ci` gates on `pnpm verify`.

**Interfaces:**
- Produces: `normalizeCjkGlyphs(raw: string): string` — maps simplified-Chinese glyphs to their JA shinjitai equivalents.

**Why a raw-string pass:** the map only ever replaces a CJK glyph with another CJK glyph — it can never touch JSON syntax (`{}[]":,` are ASCII) or schema keys (ASCII field names). So a single `String.replace` over the raw JSON, before parse, is sufficient and simpler than a recursive object walk. The map is **bounded to the glyphs G1 actually observed** — do not add speculative entries.

- [ ] **Step 1: Write the failing test** (populate the map from G1 finding (b); example glyphs shown):

```ts

  it('maps observed simplified-Chinese glyphs to JA shinjitai', () => {
    expect(normalizeCjkGlyphs('适応と応答')).toBe('適応と応答'); // 适→適
    expect(normalizeCjkGlyphs('對応')).toBe('対応');             // 對→対 (if observed)
  });
  it('leaves JSON structure and ASCII untouched', () => {
    const s = '{"summary":"适切","ts":"12.5"}';

  });

  });
```

```ts
/** Bounded simplified-Chinese → JA shinjitai glyph map. Qwen3 is zh-native and
 *  bleeds a few simplified glyphs into JA output; this normalizes ONLY the
 *  glyphs observed in the STEP-2 eval (memory runbook finding b). Not an
 *  open-ended table — each entry earns its place from real output. */
const GLYPH_MAP: Record<string, string> = {
  '适': '適', '應': '応', '對': '対', '応': '応', // ← replace with the exact G1 set

const RE = new RegExp(`[${Object.keys(GLYPH_MAP).join('')}]`, 'g');
```
